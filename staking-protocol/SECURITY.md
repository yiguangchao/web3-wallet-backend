# Security model

## Protected assets and invariants

首要保护对象是用户质押本金，其次是已经注资的奖励。系统不保证代币市场价格，也不对恶意或可升级 ERC-20 的发行方行为负责。

| 风险 | 控制措施 | 验证方式 |
|---|---|---|
| 重入 | 所有资金入口/出口使用同一重入锁，状态先更新再转账 | 单测、状态机测试、静态分析 |
| 虚假入账 | 转账前后余额差必须等于请求金额 | fee-on-transfer 回滚测试 |
| 本金被当作奖励 | 构造时强制两个代币地址不同 | 构造约束和代码审查 |
| 管理员盗取资产 | 两种受保护代币不能执行 recover | 权限单测 |
| 恶意换分发者 | 仅 owner 可提议，48 小时后才可激活 | 时间和权限单测 |
| owner 误转 | 两步所有权，候选人主动接收 | 权限单测 |
| 紧急暂停锁死本金 | 暂停仅阻止 stake/notify，withdraw/exit 保持开放 | 暂停逃生单测 |
| 奖励超发 | 新增资金先到账，旧周期剩余量纳入新速率，检查储备 | 奖励偿付不变量 |
| 签名重放 | Permit nonce、deadline、chainId 和 verifyingContract | EIP-2612 测试 |
| 舍入误差 | 先乘精度再除总质押；小额余数留在合约而非超发 | 模糊与不变量测试 |

## Trust assumptions

- 质押币和奖励币遵循稳定的 ERC-20 余额语义，不 rebasing、不黑名单冻结金库；
- owner 与 reward distributor 是不同职责，测试网之外应使用多签和硬件钱包；
- RPC 和前端可能不可用，但用户仍可直接调用已验证合约；
- 区块时间由共识层控制，奖励只使用相对时间，不依赖精确现实时间；
- 编译器、部署产物和已验证源码的哈希必须与 CI 产物一致。

## Review checklist before any value

- [ ] 固定并审阅编译器、Foundry、前端依赖锁文件；
- [ ] `forge test`、fuzz、invariant、coverage 和 Slither 全部通过；
- [ ] 独立审计人员复核奖励公式、权限和所有外部调用；
- [ ] Sepolia 完成至少一个完整奖励周期和多人交错测试；
- [ ] owner 换为多签，分发账户只持有必要奖励币；
- [ ] 前端地址、chainId、浏览器已与链上部署交叉核验；
- [ ] 暂停、用户退出、分发者轮换和所有权交接演练完成；
- [ ] 漏洞披露渠道、事件响应负责人和监控告警已建立。

## Reporting

不要在公开 issue 中披露可利用漏洞。生产使用前应配置专用安全邮箱和 PGP 公钥；当前仓库只适合作品展示和受控测试网实验。
